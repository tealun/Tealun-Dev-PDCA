# 规则遵守率记录

技能里的规则都是对模型提的要求，执行时没有拦截层。本文件记录这些规则在真实工作周期里有没有被遵守，用数据代替推测。决策见 `docs/88_planning/review-followup-20261104.md` D8。

## 记录方法

- **何时记**：每个工作周期结束时，跑 evolver 收尾的同时记录（AGENTS.md 有规定）。
- **记什么**：下面 5 道 Gate 逐条记一行。周期里没遇到的 Gate 记 `不适用`，不要算作遵守。
- **怎么判断**：只看会话记录和产物里实际出现过的内容；证据栏写出位置或原文片段。周期栏只写周期名称，不写会话编号（本仓库公开）。
- **记录方式**：`自评` 指执行本周期的 agent 自己记录；`独立` 指另一个 agent 或人只看记录做出的判断。自评偏乐观，统计时分开计算。
- **何时统计**：满 10 个周期后，按 Gate 计算遵守率（遵守 ÷ 适用），并在下方“统计”一节写出结果。遵守率持续偏低的 Gate 应由 evolver 提出改法；改法可以是简化规则，也可以把它改成脚本或 CI 检查。

## Gate 定义

| Gate | 遵守的判定 |
|---|---|
| G1 技能调用 | 触发条件满足时，第一次相关动作之前已经通过技能工具调用（或读取 SKILL.md），而不是只照着大意去做 |
| G2 先立契约 | 第一次写入之前，已经写出完成定义和一个可执行的检查 |
| G3 证据收尾 | 声称完成时附有命令输出或读回结果，而不只是描述 |
| G4 失败转交 | 出现检查失败或用户说“还是不对”时，下一步转入 bugfixer；修复附带回归测试或写明为什么没有 |
| G5 规划读台账 | planner 运行时读取演进台账，并在交接里列出用到的条目或写 `none relevant` |
