# 规划：吸收 delivery-no-pseudoblock 的四点

状态：已实现（tasker 1.9.0、planner 2.1.0、dev-pdca 1.2.0；台账 EV-20261103-001）· 2026-11-03

## 1. 理解卡

- **来源**：外部技能 `delivery-no-pseudoblock` 1.0.0（单文件，D1–D12 交付前闸门）。经对照，四点是现有套件没有覆盖的：
  1. D3/D5：最优步不得包装成可选或延后；结尾一句同样受检。
  2. D11：约束性文本（规则、技能、指令、台账防线）里不得预埋逃逸口。
  3. D12：检查必须在最后一次工具调用之后、针对将要发出的整条回复进行，不能提前当盖章。
  4. 核对写实：检查结果写出实际看到了什么，“通过 / 未命中”这类标签本身不算证据。
- **问题**：tasker 的收尾门只约束 M/L 任务的完成证据，不审查回复措辞；S 级问答和向用户提问不经过任何检查。实例：本会话中一次只读回答以“要不要做，可以先交给 planner 评估”收尾，已判明最优的下一步被包装成留给用户决定。
- **非目标**：不照搬 D7–D9（项目专属：照片、审核上架、checkStatus、地铁编码等）；不照搬“用户指出问题即视为已授权修复”，它与 tasker 的副作用确认门冲突；不要求每条回复贴 12 行快照。

## 2. 契约

- `done_definition`：tasker 新增 Delivery Gate，覆盖所有回复（含 S 级与提问），含上述 1、3、4 三点；tasker 的验证协议要求观察写实；第 2 点写进 tasker（交付物为约束性文本时）、evolver（写防线前）、planner（写开发指引前）；dev-pdca 会话规则加入 Delivery Gate；各技能版本与 CHANGELOG 更新；套件包重建。
- `validation_method`：`python3 scripts/build_suite.py --check`；`python3 scripts/check_ledger.py`；frontmatter YAML 解析；读回改动段落；用本会话那句收尾实例走一遍 Delivery Gate，确认会命中。
- `fail_condition`：新规则与 tasker 的确认门或 Post-Error Restraint Gate 矛盾；新增文字本身含 D11 所指的逃逸口；套件包超出 WorkBuddy 限制。

## 3. 决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | Delivery Gate 放在 tasker 的 Output Contract，适用于每一条回复，包括 S 级问答、状态汇报和提问 | tasker 已是“交付证据”的归属；单独新建技能会与 tasker 的收尾门重叠 |
| D2 | 合法提问的边界沿用 tasker 已有条件：需要新授权、实质扩大范围、破坏性风险、工具拿不到的输入、或属于用户的偏好与取舍。除此之外的问句和“如需 / 你定 / 回头再说”类收尾视为未过检 | 不引入“指出问题即授权”，保住确认门；同时堵住把可自决的活甩回用户 |
| D3 | 最优步规则：回复中已判明的最高价值下一步，若在授权和范围内且工具可做，就先做完再回复；做不了时写明具体阻断原因，而不是包装成可选项 | 对应 D3 |
| D4 | 检查范围是整条回复，最后一段与最后一句明确列入；“已检查”的声明不能替代对结尾的检查 | 对应 D5 |
| D5 | 检查时机：最后一次工具调用之后、对最终草稿进行；之后若又调用工具或改写回复，重新检查 | 对应 D12；本套件没有“加载闸门技能”这一步，时机约束落在检查动作本身 |
| D6 | 不要求贴快照。M/L 的结构化输出在证据账里加一行交付检查，写出结尾和下一步实际是什么；S 级不输出检查过程 | 写实但不冗长，符合用户对简洁的要求 |
| D7 | 观察写实规则放进 `tasker/references/verification.md` 的 Evidence Model：Observation 必须写出看到的内容（输出片段、数值、读回的文字），单独的“通过 / OK / 未命中”不算观察 | 对应“核对清单写实”，落在已有的证据账上 |
| D8 | 规则文本逃逸口检查（D11）定义一次，放在 tasker Delivery Gate；evolver 写防线、planner 写开发指引前引用同一条规则。检查三类：以动机为条件的禁止（应锚定行为本身）、预埋的开脱理由、自拟的豁免条件 | 三处都会产出约束性文本；单一定义避免分叉 |
| D9 | 版本：tasker 1.9.0、planner 2.1.0、dev-pdca 1.2.0；evolver 未声明版本，保持不加，变更记入 CHANGELOG | 行为变化需同步版本；不为 evolver 新引入版本字段 |
| D10 | 不派全新 agent 试跑 | 本次是在现有流程上增加一个收尾检查，不是新增技能或改写工作流；AGENTS.md 的试跑规则不适用。若后续把 Delivery Gate 扩成独立技能，再按该规则试跑 |

## 4. 假设

- A1：用户偏好简洁回复，因此不采用每条回复贴快照的做法。
